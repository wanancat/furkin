## 本次重点

### 主人跨维度随行

主人进行真实跨维度切换时，出发维度内、默认 16 格欧氏半径内、已加载、属于本人的 canonical 绒亲会随行到目标维度。支持地狱门、末地门、跨维度 `/tp` 和 `/execute in`；坐姿绒亲到达后会清除坐姿并继续跟随。

实现采用“旅行前快照 + 到达后服务端 tick 校验”，不会在旅行事件内提前移动宠物。旅行取消、目标维度变化或快照超时不会产生错误传送；不会为冷区宠物申请 chunk ticket、加载区块、重建实体或复制档案。

### 新增服务端配置

`furkin-server.toml`：

- `ownerDimensionFollowEnabled`：默认 `true`
- `ownerDimensionFollowRadius`：默认 `16`，范围 `1-64`

### 显式远召优先

同一绒亲存在同一玩家的活跃远召 pending 时，随行会让路，不取消 pending、不修改远召终态，也不会在远召失败后补做随行，避免出现“失败提示后宠物又出现”的矛盾。

## 兼容性

- 无破坏性公开 API 变更。
- 网络包结构和 `PROTOCOL_VERSION` 保持 `"2"`。
- 不新增存档 schema 字段。
- 公开 API、存档数据和原有远召/收回/死亡/复活语义保持不变。

## 验证摘要

- 服务端：无夹具 30 分钟空闲长跑全程 20 TPS，overall mean tick time `0.859-0.910 ms`。
- 最终代码压力复测：默认 3 只 P95 `1.861 ms`；12 个玩家同 tick、每人 3 只 P95 `8.558 ms`；radius 16、activeLimit 20、80 野生 cold P95 `23.352 ms`。cold 尖峰按首次路径/JIT 处理，默认 `activeLimit` 仍为 3。
- 落点安全：正常安全地面通过；向下超过 2 格无支撑、熔岩、火等危险体积会被拒绝，无法找到安全落点时该只留在原维度并记录 `NO_SAFE_LANDING`。
- 真实客户端：Overworld ↔ Nether 全员往返通过；F-26 失败反馈已由真实客户端独立复验，`OdfAlpha` 收到“远距召唤已取消，档案状态未改变”。
- 客户端帧率：开发客户端、vsync 上限 60 的稳定窗口 p50/p95 均为 60 FPS；仅启动和换维度瞬间出现低帧样本。
- 多人网络：3 只宠物、2 个 tracking 客户端时，每只显式同步 `207 bytes`、`chunkTrackers=2`；显式同步加 `PlayerEvent.StartTracking` 的两客户端总载荷约 `2484 bytes`，未发现额外广播范围。默认 3 只、10 个 tracking 客户端的载荷外推约 `12420 bytes`。

## 安装

1. 安装 Minecraft 1.19.2 与 Forge 43.2.0 或兼容的 43.x。
2. 将 `furkin-1.19.2-0.0.4.0.jar` 放入 `mods/`。
3. 启动客户端或服务端。首次运行后生成 `furkin-server.toml`，按需调整随行开关和半径。

## 已知边界

- 原版末地“终章返回”（出口传送门 -> 终章 -> 重生）不随行，属于范围外。
- 出发时已经卸载的宠物不会被强制加载。
- F-16/F-25 的 pending 让路主路径已验证；另一时序分支仍记录为“部分通过”，未扩展为所有远召竞态均已完整覆盖。
- 本轮真机性能数据来自单一 Forge 开发客户端/服务端环境；不同硬件、视距和真实生产网络的长期流量不能直接外推。
